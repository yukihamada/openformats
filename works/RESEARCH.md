# README 設計根拠（科学リサーチ）

この README は「最後まで読みたくなる」ために、UX 研究の一次情報に基づいて構成した。取得日は 2026-11-08。

## 参照した一次情報

1. **Nielsen Norman Group「F-Shaped Pattern of Reading on the Web」** (Kara Pernice, 2017, last reviewed 2026-08-19)
   https://www.nngroup.com/articles/f-shaped-pattern-reading-web-content/
   - 人は最初の 2 段落を最も読む。見出し・箇条書き・太字が無い「壁のような文章」だと F 字に走査して大半を飛ばす。
   - 対策: 重要点を最初の 2 段落に置く／見出しを情報語で始める（最初の 2 語だけで内容が伝わるように）／太字・箇条書き・番号を使う／不要な文章を削る。

2. **Nielsen Norman Group「Progressive Disclosure」** (Jakob Nielsen, 2006)
   https://www.nngroup.com/articles/progressive-disclosure/
   - 最初は最重要の少数だけ見せ、詳細は要求時に開示する。学習しやすく、エラーが減り、上級者も速い。
   - 開示の段差は 2 段まで。進み方が明白で、ラベルで期待が伝わること。

3. **Loewenstein の情報ギャップ理論**（Wikipedia「Curiosity」経由で確認, 2026-11-08）
   https://en.wikipedia.org/wiki/Curiosity
   - 好奇心は「知っていること」と「知りたいこと」の隙間（information gap）で生じる。隙間が適度なとき最も強く動機づけられる。埋めると報酬（ドーパミン）が得られる。

## どう反映したか

| 根拠 | README での実装 |
|---|---|
| 最初の 2 段落が最重要 | 冒頭に「結論から」「なぜ作ったか」を太字で配置。1 画面で価値が伝わる。 |
| 見出しは情報語で始める | 「30 秒でわかる」「実際の作品」「使い方（3 コマンド）」など、見出しの頭で内容がわかる。 |
| 壁文章を避ける | 箇条書き・表・コードブロック・太字を多用。長い段落を作らない。 |
| 段階的開示（2 段） | 設計哲学・エンベロープ全フィールドは `<details>` で折りたたみ。最重要は常時表示。 |
| 情報ギャップで引き込む | 冒頭で「あなたの作品は、あなたの手元に残るか？」と問いを立て、末尾「冒頭の問いの答え」で回収。読み進める動機を構造で作る。 |
| 具体的な証拠 | 抽象論でなく、実在する 3 作品（実データ JSON・SHA-256・出典）を `works/` に置いて提示。 |

## 未確認・限界

- 実際の読者による離脱率・読了率は未計測（A/B テスト未実施）。上記は既存研究の適用であり、この README 固有の効果測定ではない。
- `<details>` の折りたたみは GitHub の Markdown で表示されるが、他環境での見え方は未確認。
